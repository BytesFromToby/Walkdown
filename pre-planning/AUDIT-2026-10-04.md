# Spec audit, 2026-10-04

A pass over the whole project for behavior that is undocumented or does not match its spec.
Method: scripted checks, plus a full pipeline run on superpowers and 14 fixture repositories
chosen to exercise every check, with every emitted check and field compared to
`stages/CONTRACT.md`.

## Checks run, and what they found

| Check | Result |
|---|---|
| Every script has a spec and tests; every spec and test has a script | Clean. (`stages/04-phrases/tests/test_table.py` tests the pattern table, a data file: expected.) |
| Every check the code emits is in CONTRACT | Clean. |
| Every field the code emits is in CONTRACT | **35 fields across 13 checks were undocumented.** Fixed: "Additional fields" table in CONTRACT. |
| Every check has a grader gate (a known positive) | **`struct.mcp` had none**, though built 2026-09-29. Fixed: fixture `01-inventory/class17-mcp` (stdio and http servers, environment names only, prose not counted). **`read.unread` and `cap.load-bytes` had none**: fixed with an archive fixture in `02-reader` and rows on existing stage 5 fixtures. |

## Accepted gaps (recorded, not fixed)

- `graph.unscanned` has no grader gate. It reports a limit (a file the graph could not scan),
  not a detection; a fixture would need a new file in the graph fixture repo that shifts other
  answers. Exercised by unit tests and visible on real runs.
- `inv.pin` and `inv.file` have no gate rows: they are the census every other check depends
  on, so any failure shows up in every other gate.
- `soft.label`, `soft.sweep` are measured (recall), never required, by design: they depend on
  a model. `soft.read`, `soft.compare`, `soft.agree` have no rows: relational reads are prose,
  and the comparison labeler (Laya) is retired.
